# Reglas de trabajo del proyecto CATALOGOS_KM

Estas reglas las puso el dueño del proyecto (Wilmer) y se deben cumplir SIEMPRE, en cada sesión.

## 1. Explicar todo lo que se implementa
- Todo lo que se implemente se explica.
- La explicación debe ser **sencilla, no tan técnica**, fácil de entender.
- **Cada línea de código** que se agregue o modifique se explica.

## 2. Claude NO agrega el código: lo agrega el dueño
- Claude **no escribe ni modifica código en los archivos**. El dueño lo agrega él mismo.
- Claude solo **muestra** el código en la conversación, indicando **en qué archivo** va y **en qué parte** del archivo (línea, función o sección).
- Junto con eso, explicar línea por línea qué hace ese código.
- **Excepción:** Claude solo agrega código directamente cuando el dueño se lo pida de forma explícita.

## 3. Base de datos: solo con permiso
- Cualquier modificación en la base de datos (crear/borrar tablas, cambiar columnas, insertar, actualizar o borrar datos, migraciones, etc.) **requiere permiso explícito** del dueño antes de hacerse.
- Lo mismo aplica para cualquier cambio delicado o difícil de deshacer: primero se pregunta.

## 4. Si hay dudas, preguntar
- Si algo no está claro, se pregunta antes de suponer.

## 5. Idioma
- Todas las explicaciones y comunicación en **español**.

## Pendiente
- Más adelante se crearán *skills* (habilidades) personalizadas para el proyecto.
